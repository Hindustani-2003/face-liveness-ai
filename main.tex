\vspace*{0.5cm}
{\Large \textbf{Abstract}}
\end{center}

\vspace{1.0cm}
\noindent This project focuses on a critical challenge in modern biometric security ecosystems---detecting and mitigating Presentation Attacks (spoofing) in 2D facial recognition systems. Traditional facial recognition engines are acutely vulnerable to non-live artifacts such as high-resolution printed photos, digital screen replays, and 3D silicone masks. Accurate calculation and analysis of facial liveness metrics are crucial for preventing unauthorized access, protecting user credentials, and ensuring frictionless identity verification.

\vspace{0.6cm}
\noindent To solve this, our project presents \textbf{FaceLiveness AI}, an enterprise-grade biometric authentication platform engineered with browser-native deep learning models and real-time interactive liveness verification. The system executes client-side WebGL acceleration using \texttt{face-api.js} (TensorFlow.js) to compute Eye Aspect Ratio (EAR) blink state-machine transitions, head yaw rotation ratios, and vertical mouth opening metrics.

\vspace{0.6cm}
\noindent Verified facial crops are mapped into a 128-dimensional real-valued vector space ($\mathbb{R}^{128}$) and matched via 1:1 Euclidean distance ($D(\mathbf{A},\mathbf{B}) < 0.60$) against cloud-hosted MySQL databases on Aiven, managed via tRPC, Drizzle ORM, and multi-stage Alpine Docker containers deployed on Render PaaS with automated HTTPS SSL encryption.

\section{Introduction}
\label{sec:introduction}

\subsection{Motivation}
In modern biometric security systems, once a user initiates authentication, the facial stream must undergo real-time liveness verification before identity matching occurs. Traditional knowledge-based passwords and PINs are increasingly susceptible to phishing and credential theft. Biometric face recognition provides a frictionless user experience by utilizing unique physiological traits.

However, 2D facial recognition suffers from acute vulnerability to Presentation Attacks (PAs), where spoofing artifacts like printed photos or video replays bypass basic cameras. Motivated by this issue, our project aims to build an interactive, browser-native face liveness detection engine that verifies physical presence in real-time, helping digital systems prevent unauthorized access and improve security.

\subsection{Objectives}
The main goals of this project are:
\begin{itemize}
    \item Build a client-side deep learning liveness detection engine running in WebGL.
    \item Implement Eye Aspect Ratio (EAR) blink tracking and randomized head motion challenges.
    \item Construct a type-safe tRPC API router connected to cloud MySQL.
    \item Achieve sub-4-second authentication times with $> 98\%$ accuracy and zero server GPU hosting costs.
    \item Deploy the full-stack system on public cloud infrastructure with automated HTTPS SSL encryption.
\end{itemize}

\section{Methodology}
\label{sec:methodology}

\subsection{Overview of the Approach}
We implemented a client-side deep learning inference engine using \texttt{face-api.js} (TensorFlow.js) to extract 68 2D facial landmarks. Liveness is verified through Eye Aspect Ratio (EAR) blink tracking and head rotation ratios. Extracted 128-dimensional facial descriptors ($\mathbb{R}^{128}$) are transmitted via tRPC to a Node.js server for 1:1 Euclidean distance matching against templates in MySQL.

\subsection{Tools and Technologies Used}
\begin{itemize}
    \item \textbf{React 19 \& Vite:} User interface and high-performance compilation.
    \item \textbf{face-api.js (TensorFlow.js):} Browser-native MobileNetV2 and ResNet-34 models.
    \item \textbf{tRPC \& Zod:} End-to-end type-safe API communication and validation.
    \item \textbf{Node.js \& Express:} Backend runtime and route middleware.
    \item \textbf{Drizzle ORM \& Aiven MySQL 8.0:} Type-safe database queries and managed cloud storage.
    \item \textbf{Docker \& Render PaaS:} Multi-stage containerization and automated cloud deployment.
\end{itemize}

\subsection{Development Workflow}
\begin{enumerate}
    \item Real-time camera frame acquisition via WebRTC.
    \item Stage 1 EAR Eye Aspect Ratio blink verification:
    \begin{equation}
    \text{EAR} = \frac{\|P_{37} - P_{41}\| + \|P_{38} - P_{40}\|}{2 \cdot \|P_{36} - P_{39}\|}
    \end{equation}
    \item Stage 2 Randomized physical challenge (Head turn / Mouth open).
    \item 1:1 Euclidean Descriptor Distance matching ($D(\mathbf{A},\mathbf{B}) < 0.60$).
\end{enumerate}

\subsection{Challenges and Mitigations}
\begin{itemize}
    \item \textbf{Client Hardware Variability:} Solved via TinyFaceDetector lightweight model.
    \item \textbf{Aiven SSL Connections:} Resolved using \texttt{rejectUnauthorized: false} configuration.
    \item \textbf{Multi-Face Spoofing:} Blocked using multi-face detection guards.
\end{itemize}

\subsection{Scalability and Deployment Considerations}
The architecture scales horizontally using multi-stage Docker containers hosted on Render PaaS connected to cloud MySQL.

\section{Implications and Policy Recommendations}
\label{sec:implications}

\subsection{Operational Implications for Biometric Security}
Biometric authentication replaces legacy passwords with frictionless face verification, significantly improving user experience while enhancing security.

\subsection{Policy Recommendations}
\begin{itemize}
    \item Enforce HTTPS TLS 1.3 encryption across all biometric transmission channels.
    \item Store embeddings as irreversible mathematical vectors ($\mathbb{R}^{128}$).
    \item Provide automated account deletion features for compliance with GDPR.
\end{itemize}

\subsection{Future Scope}
\begin{itemize}
    \item Integration of WebXR 3D depth sensors.
    \item WebAssembly SIMD hardware acceleration for older mobile devices.
\end{itemize}
